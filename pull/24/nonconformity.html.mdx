---
title: Nonconformity scores
description: Score functions used to turn predictions and truths into calibration scores
---

A score is method config: pass it as `score=` when constructing a method, or
leave it out to take the method's default. Each concrete score carries a `kind`
tag (`"absolute"`, `"signed"`, `"quantile"`), which is what lets a configured
method survive `model_validate(model_dump())`.

A custom score subclasses `ScoreFunction` (or one of the built-ins) and declares
its own tag, e.g. `kind: Literal["scaled"] = "scaled"`. Subclassing a built-in
without declaring a new tag raises `TypeError` when the class is defined,
because the score would otherwise reload as its parent. To reload a dumped
method holding a custom score, import the module that defines the score first.

### `AbsoluteResidual`

Bases: <code>[ScoreFunction](#conformalforecast.base.ScoreFunction)</code>

Nonconformity score defined as the absolute residual |truth - prediction|.

This is the simplest and most widely used score function in conformal
prediction. It produces symmetric intervals around the point forecast.

#### `AbsoluteResidual.CONSUMES_QUANTILES`

```python
CONSUMES_QUANTILES: bool = False
```

#### `AbsoluteResidual.fit`

```python
fit(prediction, truth)
```

Fit any internal parameters of the score function (e.g. scale
estimates for normalised residuals). Default: no-op.

Called by the method's ``fit`` **before** the first call to :meth:`score` on the
calibration data, so implementations can assume that ``prediction`` and
``truth`` are the full calibration arrays.

Parameters
----------
prediction : Forecast, shape (n_series, n_samples, horizon)
truth : Forecast, shape (n_series, n_samples, horizon)

### `SignedResidual`

Bases: <code>[ScoreFunction](#conformalforecast.base.ScoreFunction)</code>

Nonconformity score defined as the signed residual ``truth - prediction``.

Unlike :class:`AbsoluteResidual`, this score preserves directional
information. Positive scores indicate truth was above prediction;
negative scores indicate truth was below. Used by methods that produce
asymmetric intervals around the point forecast (e.g. SPCI).

#### `SignedResidual.invert`

```python
invert(prediction, score_threshold)
```

Produce an asymmetric interval around the point forecast.

Parameters
----------
prediction : Forecast, shape (n_series, n_samples, horizon)
score_threshold : NDArray, shape (n_series, horizon, 2) or                 (n_series, n_samples, horizon, 2)
    For each cell, the last axis is ``(lower_offset, upper_offset)``.
    The interval becomes ``[prediction + lower_offset, prediction +
    upper_offset]``. Note that ``lower_offset`` is typically negative
    and ``upper_offset`` positive for non-degenerate intervals.

```
The 3-D form is one offset pair per ``(series, horizon)`` cell,
broadcast over every sample -- what :meth:`interval` produces. The
4-D form carries a distinct pair per sample, which is what a method
whose offsets vary window-to-window needs; see
:meth:`~conformalforecast.methods.base.ConformalMethod.calibration_intervals`.
NaN offsets propagate to NaN bounds, marking a window as not
evaluable.
```

Returns
-------
Interval, shape (n_series, n_samples, horizon, 2)
    Last axis is ``(lower, upper)``.

Raises
------
ValueError
    If ``score_threshold`` is not 3-D or 4-D with trailing axis of size 2.

#### `SignedResidual.kind`

```python
kind: Literal['signed'] = 'signed'
```

Returns
-------
scores : NDArray, shape (n_series, n_samples, horizon)
    Signed residuals (truth - prediction). Positive when truth exceeds

### `QuantileScore`

Bases: <code>[ScoreFunction](#conformalforecast.base.ScoreFunction)</code>

Nonconformity score for Conformalized Quantile Regression (CQR).

Unlike :class:`AbsoluteResidual`, the ``prediction`` input is a pair of
quantile forecasts ``(q_lo, q_hi)`` rather than a point forecast. The
score measures how far truth falls outside the predicted quantile
interval:

.. math::

```
E_i = \max\{q_{\text{lo}}(X_i) - Y_i,\; Y_i - q_{\text{hi}}(X_i)\}
```

Negative scores mean truth is inside the predicted interval; positive
scores mean it falls outside (above the upper bound or below the lower
bound). :meth:`invert` widens the predicted interval symmetrically by
the score threshold.

```python

```

```python

```

Widen the predicted quantile interval by ``score_threshold``.

Parameters

    Either scalar, shape ``(n_series,)``, or shape
    ``(n_series, horizon)``. Broadcast against ``prediction`` along

Returns
-------
Interval, shape (n_series, n_samples, horizon, 2)
    Last axis is ``(lower, upper)`` with
    ``lower = q_lo - threshold`` and ``upper = q_hi + threshold``.

### `ScoreField`

```python
ScoreField = Annotated[SerializeAsAny[ScoreFunction] | None, BeforeValidator(_from_registry), WithJsonSchema({'anyOf': score_options(BUILTIN_KINDS), 'default': None})]
```

A nonconformity score as method config, or ``None`` for the method's default.

Accepts a :class:`~conformalforecast.base.ScoreFunction` instance or its dump.
``SerializeAsAny`` makes a subclass dump its own fields (and its own ``kind``),
and the before-validator rebuilds a dump as the class its ``kind`` names, so a
configured score -- custom ones included, once their module is imported --
survives ``model_validate(model_dump())``.

The schema here lists every built-in kind; ``ConformalMethod`` narrows it to the
kinds each method accepts.
